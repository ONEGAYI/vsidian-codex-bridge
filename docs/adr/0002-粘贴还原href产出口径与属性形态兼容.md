# ADR-0002：Codex 粘贴还原——href 产出口径与属性形态兼容

- 状态：**已按推荐先行实施，待用户追认**（票 #2，2026-10-16）
- 背景：票 #2 带两项待决策——① href 含空格与 `:行号` 时的产出形态（`%20` 编码 / 宽松字面目标），与 Vsidian 宽松链接（[#152](https://github.com/ONEGAYI/vsidian/issues/152)）及行号锚点（[vsidian#534](https://github.com/ONEGAYI/vsidian/issues/534)）的衔接口径；② Codex 端属性形态变化时的兼容面（是否保留旧形态识别）。实施原则（任务书决策 1）：**不自行发明——宿主怎么解析，规则就怎么产出**。

## 宿主口径调研结论

以下结论全部读自 vsidian 主仓库 `origin/main @ 301d2c16`（batch-2 PR #564 合入点）的 git 对象，未触碰其工作树：

| 口径 | 出处 | 结论 |
| --- | --- | --- |
| 粘贴侧 URL 出口 | `src/webview/htmlToMarkdown.ts` 的 `safeUrl` | URL 槽（`url: true`）的统一出口：trim → markdown-it `validateLink` 白名单（剥控制字符后校验，危险协议拒绝）→ 空格替换 `%20`、圆括号 `%28`/`%29`。**冒号不在编码表，明文透传** |
| 行号锚点解析 | `src/shared/vaultLink.ts` 的 `splitLineSuffix`（`src/host/linkTarget.ts` 消费；T04/#534） | 本地路径段尾部 `:十进制正整数` 才是行号后缀；**仅认明文冒号，`%3A` 不剥**（上游注释原话：工具输出复制的是明文）；行号与 fragment 同报为混合定位、整次非法 |
| 宽松链接 | #152 症状与实现 | 双视图把**未编码空格**目标渲染为链接（Obsidian 兼容）；解析侧 percent-decode 容错——原样与已编码两种写法解析到**同一目标** |
| 槽值转义 | `escapeText`（同 htmlToMarkdown.ts） | text/attribute/捕获组槽值经内置转义（`` `*_~{}[]<># `` 及行首列表标记：`2.`→`2\.`、`-`/`+`→`\-`）；**模板字面零转义**（作者声明的静态 Markdown 结构）；children 槽不二次转义 |

三条口径拼起来的关键事实：**粘贴产出的 href 全程由宿主 safeUrl 收口**（空格→`%20`、括号→`%28/%29`、白名单协议），而明文冒号恰好透传、恰好是行号解析唯一认的形态；解析侧对 `%20` 与字面空格又解析同目标。两端自洽，规则侧任何预加工（自行编码、自剥行号）都只会制造与宿主不一致的第三种形态。

## 决策一：href 产出形态——`url: true` 槽直取属性，零预加工

- url 槽 `source: { kind: 'attribute' }`（**非** attribute-regex 变换）+ `url: true`：含空格的 href（如 `notes/fix list.md:12`）由宿主 safeUrl 统一编码为 `notes/fix%20list.md:12`——空格编码、括号编码、协议白名单三件事全部归宿主，组件不做也不做不了（声明式规则无处理钩子，这正是选择直取的理由）；
- 明文冒号透传 ⇒ `:行号` 后缀原样到达 Markdown，点击侧按 #534 口径剥出行号定位；`%3A` 形态不产出（宿主不产、组件不造，行号解析也不认）。

## 决策二：label 槽取属性（票面当前形态）

票面形态的 span 文本是 **Markdown 源码原文**（含 `[label](href)` 完整语法）。label 若取 text，槽值经 `escapeText` 会打成 `\[...\](...)` 字面文本——正是本票要修的症状。故 label 从 `data-prompt-link-label` 属性取（Codex 已抽好的纯显示文本），span 自身文本被规则产出整体替换。

## 决策三：旧属性形态兼容——两规则并存，id 升序票面先行

上游规格/测试中存在历史变体：单 `data-prompt-link-url` 属性、label 取 span 文本——见集成夹具 `test/integration/addonFixtures/addon-paste-rules/extension.js` 与浏览器契约套件 `test/browser/addonPasteRules.mjs` 的 snapshotV1（该形态已在真实回放中验证）。保留识别（低成本向后兼容）：变体规则 `codex-prompt-link-legacy-url` 与上游已验证声明**逐字段等价**（仅 id 不同，契约测试钉住）。两规则优先级同为缺省 0，宿主确定性排序按规则 ID 升序——`codex-prompt-link` 字典序在前，两形态属性共存时以票面形态（属性重建）为准。

## 「`2\.` 类列表标记转义不再发生」的机制说明

无规则时，span（文本 = Markdown 源码原文）被内置转换当普通正文：`escapeText` 转义 `[`/`]`，行首 `2.`/`-`/`+` 列表标记加反斜杠——整段源码变伤。规则接管后该片段的产出 = **模板字面（`[]()` 零转义）+ 属性槽值**，span 自身文本不再作为正文输出——转义伤在「由规则产出的片段」上不再发生。真格式（strong/code/pre）在 span 之外由内置转换正常处理，规则不越界（规格 P-U03）。

## 后果与边界

- 规则集是纯数据（JSON 可序列化、无函数），注册在 enable 生命周期（`registerCodexPasteRules`，`src/paste-rules.ts`）；普通拒绝（`invalid-declaration`/`duplicate-id`/`too-many`/`released`）只记录不抛异常——降级底线：宿主回落内置转换；注册成功不提前 dispose（停用/故障/代次结束由平台撤回，对齐上游夹具形态）；
- 页面侧零代码：声明式规则经宿主广播在既有 HTML→Markdown 遍历中消费，`dist/editor.js` 空工厂占位留给 bridge#3；
- 转换语义（命中/回退/编码/格式保留）归 vsidian 侧测试验证；组件侧契约测试（`test/paste-rules.test.ts`）钉住声明形状、与上游已验证形态的等价性、样本回放核对与注册行为，不复制宿主转换器；
- Codex 端属性形态若再现新变体，按同模式扩规则（保持与上游/票面声明的逐字段等价断言），并同步更新本 ADR 的兼容面清单。

## 已知边界与未尽事项

- 票面形态（label + href 双属性）的真实 Codex 剪贴板全样本未在仓库内归档——组件侧回放核对基于票面描述与上游已验证变体构造；上游浏览器/真宿主层已验证的是变体形态。若用户实测票面形态样本与描述不符（如属性名再有出入），按决策三同模式扩规则即可；
- label 属性值若含 Markdown 特殊字符或行首列表标记，仍会经宿主 `escapeText` 转义（宿主固化语义，规则语言无豁免路径）——显示文本通常不含这些形态，且转义不影响链接结构本身；如未来出现真实反例，需上游扩展槽转义控制面，不在本组件可解范围。
